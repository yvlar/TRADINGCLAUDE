# Moat #2 — Coûts de transfert (switching costs)

Les clients restent parce que **changer coûte cher** — en argent, en temps, en risque, ou en disruption opérationnelle. C'est un des moats les plus durables identifiés par Dorsey.

## Mécanique

Le client paie une "taxe d'inertie" pour rester. Plus le coût de changement est élevé vs le bénéfice marginal d'un concurrent, plus le moat est solide.

## Trois types de coûts de transfert

### 1. Coûts financiers
- Frais de pénalité contractuelle
- Coûts d'implémentation d'un nouveau système (ERP, banque d'entreprise)
- Investissements spécifiques irrécupérables

### 2. Coûts en temps et complexité
- Apprentissage d'un nouvel outil
- Migration de données
- Formation des équipes
- Réintégration de processus

### 3. Coûts en risque
- Risque opérationnel pendant la transition
- Risque de perte de données
- Risque de discontinuité service-clients

## Industries à switching costs élevés

### Logiciels d'entreprise (B2B SaaS)
- **Salesforce** : intégrations multiples, données historiques, formation des équipes, customisations spécifiques
- **SAP** : implémentation 18-36 mois, coûts millions, risque opérationnel énorme
- **Microsoft Office 365** : compatibilité fichiers, formation utilisateurs, intégrations Outlook/Teams

**Test** : combien d'années ça prendrait à un concurrent pour reproduire la valeur de l'écosystème ? Si > 5 ans, switching cost est un moat majeur.

### Services bancaires d'entreprise
- Cash management, paie automatisée, lignes de crédit
- Changer de banque demande la mise à jour de centaines de fournisseurs et clients
- Risque de disruption élevé pour les opérations quotidiennes

C'est pourquoi les **banques d'entreprise** ont des marges supérieures aux banques de détail.

### Plateformes médicales et financières
- **Epic Systems** (DME hospitalier) : moat ultra-durable, 10+ ans de migration possible
- **Bloomberg Terminal** : 24 000$/an/utilisateur mais workflow ancré
- **FactSet, Refinitiv** : intégrations dans les modèles d'analystes

### Asset managers institutionnels
- Mandats de pension/dotation : pénalité de transfert + risque de performance pendant transition + relation manager-client = inertie naturelle
- Berkshire investments mid 90s : Buffett a explicitement misé sur cette inertie

## Exemples canadiens

### Constellation Software (CSU.TO)
**Le cas d'école canadien.** Logiciels verticaux pour niches (gestion municipalités, dispatch police, restaurants régionaux). Switching costs **massifs** :
- Logiciel critique mais hyper-niche, pas de remplaçant viable
- Customisations spécifiques accumulées sur 10-20 ans
- Formation utilisateurs sur la durée
- Données historiques difficilement migrables

Résultat : ROIC 25-30 % durable, prix d'achat répétable sur acquisitions identiques.

### Open Text (OTEX.TO)
Information management entreprise — switching costs similaires (intégrations + données + formation). ROIC moins spectaculaire que CSU mais durable.

## Industries à switching costs faibles

À éviter pour la prime de qualité :
- **Restaurants** : un client peut changer instantanément
- **Vêtements grand public** : pas de switching cost
- **Hôtellerie indépendante** : programmes de loyalty offrent switching cost mais limité
- **Compagnies aériennes** : programmes loyalty sont de faux switching costs (le voyageur compare souvent les prix)

## Drapeaux rouges sur les switching costs

### 1. Concurrence par "rip and replace"
Si un concurrent offre la migration **gratuite** (Salesforce vs Oracle CRM dans les années 2010), il neutralise le switching cost. Surveillance : les concurrents subventionnent-ils la migration ?

### 2. Standards ouverts émergents
Les API ouvertes et formats standards (PDF, SQL, REST) réduisent le switching cost. Un éditeur dont l'avantage repose sur format propriétaire est exposé.

### 3. Cloud/SaaS migration
Le passage on-premise → cloud a brisé beaucoup de switching costs traditionnels. Une entreprise ne sera plus accrochée à un éditeur juste parce que migrer le serveur est compliqué.

### 4. Génération de utilisateurs nouveaux
Si les nouveaux clients de l'industrie choisissent **majoritairement** un concurrent, le moat existant ne protège que le legacy. À terme, le legacy meurt avec ses clients.

## Calibration du moat de switching costs

### Wide moat
- Produit critique aux opérations
- Implémentation > 12 mois
- Données historiques irremplaçables
- Aucun migration path facile
- Exemple : Epic, SAP enterprise, Bloomberg, CSU verticals

### Narrow moat
- Produit important mais pas critique
- Implémentation 3-6 mois
- Données migrables avec effort
- Concurrents existants viables
- Exemple : CRM mid-market, banque retail entreprise PME

### Pas de moat
- Produit substituable
- Migration trivial (cloud-native, API standards)
- Pas de coûts de transfert significatifs
- Exemple : email basique, hébergement web, comptes bancaires personnels

## Synergie avec d'autres moats

Les switching costs amplifient les autres moats :
- **Switching costs + effets de réseau** = combo très durable (Microsoft Teams)
- **Switching costs + marque** = pricing power additionnel (Apple écosystème)
- **Switching costs + scale** = défense contre les insurgents (banques)

Une entreprise avec **deux moats simultanés** est typiquement plus durable qu'une avec un seul moat très large.
